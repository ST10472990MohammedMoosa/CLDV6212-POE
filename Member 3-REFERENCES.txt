The HTTP functions are responsible for processing requests and producing responses. The validator applies upload rules, while the repository contains the Azure Files operations.

Azure Files provides managed file shares that applications can access using Azure Storage client libraries (Microsoft, 2025a). This implementation uses the Azure.Storage.Files.Shares namespace and its file-share clients (Microsoft, 2026a).

Azure File Share

The staff-docs Azure File Share stores operational PDF documents used by CoffeeNChill staff.

Example documents include:

Barista recipe sheets
Equipment cleaning manuals
Health and safety policies
Operational procedures
Staff training documents

The implementation uses:

ShareClient to connect to or create the file share
ShareDirectoryClient to access the share's root directory
ShareFileClient to create, inspect, upload and download individual files

These clients form part of the Azure Files SDK for .NET (Microsoft, 2025b; Microsoft, 2026b; Microsoft, 2026c; Microsoft, 2026d).

API Endpoints
Method	Endpoint	Description	Successful status
POST	/api/documents/upload	Upload a valid PDF staff document	201 Created
GET	/api/documents	Retrieve a list of stored documents	200 OK
GET	/api/documents/download/{fileName}	Download a stored document	200 OK

The endpoints use HTTP-triggered Azure Functions with explicit methods and routes (Microsoft, 2025c).

Upload Staff Document
POST /api/documents/upload
Content-Type: multipart/form-data

The request must contain a form-data field named file.

Example successful response:

{
  "fileName": "barista-recipe.pdf",
  "sizeInBytes": 86468,
  "lastModified": "2026-09-02T13:00:22+00:00",
  "contentType": "application/pdf"
}
List Staff Documents
GET /api/documents

Example successful response:

[
  {
    "fileName": "barista-recipe.pdf",
    "sizeInBytes": 86468,
    "lastModified": "2026-09-02T13:00:22+00:00",
    "contentType": "application/pdf"
  }
]
Download Staff Document
GET /api/documents/download/barista-recipe.pdf

The endpoint checks whether the requested file exists and then returns its stream as a downloadable PDF. The Azure Files download operation reads the stored content and its associated properties (Microsoft, 2026f).

Document Metadata

Upload and listing responses use the following metadata:

Property	Description
fileName	Name of the document stored in Azure Files
sizeInBytes	Size of the stored document in bytes
lastModified	Date and time when the document was last modified
contentType	MIME type associated with the document
PDF Validation

A document must pass all of the following validation checks before it is uploaded:

A file must be included in the multipart form-data request.
The file must not be empty.
The filename must end in .pdf.
The MIME type must be application/pdf or application/octet-stream.
The file must not exceed 10 MB.
The content must begin with the %PDF- signature.
A file with the same name must not already exist.

Checking the file extension, MIME type and signature together prevents a renamed non-PDF file from being accepted only because its filename ends in .pdf.

application/octet-stream is accepted because some API clients send a valid PDF using the generic binary MIME type. The extension and signature checks still apply.

HTTP Status Codes
Status	Scenario
200 OK	Document list or download returned successfully
201 Created	Valid PDF uploaded successfully
400 Bad Request	Missing file, empty file, invalid type, invalid size or invalid PDF signature
404 Not Found	Requested document does not exist
409 Conflict	A document with the same filename already exists
500 Internal Server Error	Unexpected application or Azure Storage failure

Dependency Injection

The repository is registered in Program.cs:

builder.Services.AddSingleton<IStaffDocumentRepository, StaffDocumentRepository>();

The Azure Functions receive the repository through constructor injection. This keeps the HTTP functions separate from the Azure Files implementation and makes the design easier to maintain and test.

Azurite Setup

Azurite is used for the local Azure Functions host storage.

Run the Azurite Docker container:

docker run -d --name coffeenchill-azurite `
  -p 10000:10000 `
  -p 10001:10001 `
  -p 10002:10002 `
  mcr.microsoft.com/azure-storage/azurite

If the container already exists but is stopped:

docker start coffeenchill-azurite

Azurite supports local Blob, Queue and Table Storage development, but it does not emulate Azure Files. The staff document repository therefore uses a real Azure Storage Account and File Share, while AzureWebJobsStorage uses Azurite (Microsoft, 2025d).
